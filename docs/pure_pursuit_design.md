## 1. 입출력 규격 — 자전거 모델과 동일하게

### 1.1 규격
논문 식(1)과 manual_drive.m의 모델은 같은 **뒤 차축 기준 기구학 자전거 모델**입니다.
ẋ = v·cos θ,  ẏ = v·sin θ,  θ̇ = v·tan δ / L

그래서 제어기의 **입력 = 모델의 출력(상태)**, **출력 = 모델의 입력(명령)**으로 맞춥니다.

| 구분 | 변수 | 단위·약속 |
|---|---|---|
| 입력(상태) | x, y | m, 뒤 차축 중앙 p_v. MATLAB x = Unity X, MATLAB y = Unity Z (원점 = Plane 중심) |
| | yaw (θcar) | rad, +x축에서 반시계 +, (−π, π]. Unity Rotation Y = 90° − yaw |
| | v | m/s, 전진 + |
| | δ (현재 실제 조향각) | rad, 왼쪽 +. **Step 1에서 시작 자세 방향 θcar + δ에 필요** |
| 출력(명령) | δ_cmd | rad, ±30°로 자름 |
| | v_cmd | m/s (일정 목표속도 또는 곡률 기반) |
| 액추에이터 | 조향속도 90°/s, 가속 1.0, 감속 2.0 m/s², vMax 1.5 | manual_drive와 동일하게 적용 |
| 주기 | dt = 0.02 s (50 Hz) | manual_drive와 동일 |

계획한 함수 형태(이름은 검토 때 바꿔도 됨):
```
p              = vehicle_params();                 % L, δmax, 조향속도, 가속, dt … 한 곳에서 관리
ref            = load_reference_path(file);        % x, y, s, ψ(접선각), κ(곡률), 폐루프
[u, dbg, mem]  = pure_pursuit_step(st, ref, p, mem) % 제어기: u = (δ_cmd, v_cmd), dbg = 시각화·기록용 내부값
st             = bicycle_step(st, u, p, dt)        % 모델: 조향속도·가속 제한 + 기구학 적분
```
`dbg`에는 p_w, p_d, p_l, L_f, η, κ, R, 원 중심, r_min, α, β, τ 등이 들어가며, 기록과 Unity 표시에 그대로 쓰입니다.

### 1.2 manual_drive.m 공용화 — 의도 설명 (결정은 검토 때)
지금은 모델 식, 차량 파라미터(L·δmax·조향속도·가속), Unity 좌표 변환, TCP 전송이 모두 manual_drive.m 안에 들어 있습니다. pure pursuit도 이 부분이 **완전히 똑같아야** 합니다.

- **복사하면 생기는 문제:** 한쪽만 고쳐지기 쉽습니다. 예를 들어 L을 측정값 0.59로 바꿀 때 한 파일만 고치면, 수동 주행과 PP 결과가 서로 다른 차를 기준으로 하게 됩니다.
- **공용화 의도:**
  - `vehicle_params.m`(파라미터), `bicycle_step.m`(모델), `unity_link.m`(연결·전송)으로 빼 둡니다.
  - manual_drive는 키보드가, pure_pursuit_control은 제어기가 명령을 만듭니다. "운전자"만 다르고 차(모델)는 하나가 됩니다.
- **manual_drive에서 바뀌는 곳:**
  - 23–32행: 파라미터 → `vehicle_params()`
  - 92–98행: 기구학 → `bicycle_step` 중 기구학 부분
  - 100–108행: 전송 → `unity_link`
  - 키 입력·가감속 페달 로직은 manual_drive에 그대로 남깁니다(페달은 v_cmd와 성격이 달라서).
- **동작 차이:** 원칙적으로 없습니다. 단, L을 0.60 → 0.59로 고치면 수동 주행의 회전이 아주 조금 달라집니다.
- **대안:** manual_drive는 그대로 두고, 같은 식을 새 파일에 복사만 할 수도 있습니다. 그 경우 L 등은 수동으로 맞춰야 합니다.

## 2. 논문 개념과 적용 알고리즘

### 2.1 기본 Pure Pursuit — 선행점을 찍고 원을 그린다 (논문 2.1절)
1. **선행점 p_l 고르기:** 경로 위에서 차(p_v)로부터 약 L_f만큼 앞에 있는 점을 고릅니다. 방법은 두 가지입니다.
   - (a) p_v를 중심으로 반지름 L_f인 원과 경로의 교점. 교점이 여러 개이거나 아예 없을 수 있습니다.
   - (b) Campbell 방식: 가장 가까운 경로점 p_w를 찾고, 거기서 경로를 따라 거리를 누적해 L_f가 되는 점. 항상 하나만 나옵니다. 논문은 이 방식을 기반으로 합니다.
2. **원(호) 그리기:** p_v를 지나고 차의 진행 방향에 접하면서 p_l을 지나는 원은 단 하나입니다.
   - η = 차 방향과 (p_v → p_l) 벡터 사이 각(논문 식(2)의 θ)이라 하면, 삼각형 (p_v, p_l, 중심 o)에서 사인법칙으로 L_f / sin 2η = R / sin(π/2 − η)입니다.
   - 정리하면 **L_f = 2R sin η → κ = 1/R = 2 sin η / L_f** (식 2)
   - 원 중심: o = p_v + R·(−sin θcar, cos θcar). R의 부호가 +이면 왼쪽으로 도는 원입니다. 호 p_v→p_l의 중심각은 2η입니다.
3. **조향각:** 애커만 기하에서 tan δ = L/R이므로 **δ = atan(κL) = atan(2L sin η / L_f)** (식 3)

### 2.2 기존 방법의 한계 (논문 2.2–2.3절)
- **L_f 트레이드오프:**
  - L_f가 작으면 경로에 붙을 때 방향 오차가 남아 진동합니다.
  - L_f가 크면 수렴이 느리고 코너를 안쪽으로 자릅니다.
  - 원인: 위치만 보고, 차와 경로의 방향 관계는 보지 않기 때문입니다.
- **코너 컷팅:** 선행점이 놓인 곳의 곡률이 차 근처 곡률보다 크면(직선에서 코너로 들어갈 때), 그린 원의 반지름이 실제 코너 반지름과 달라져서 차가 안쪽으로 파고듭니다. 코너를 빠져나올 때는 거의 생기지 않습니다.
- **기존 보완책과 한계:**
  - L_f를 속도에 비례하게 잡기(Kuwata): 횡오차가 클 때 부드럽게 수렴하지 못합니다.
  - 오프셋 두기(Andersen): 오프셋의 최적값이 곡률마다 다릅니다.

### 2.3 제안 방법 Step 1 — Dubins 경로로 p_d 고르기 (논문 3.1절, Algorithm 1)
- **목적:** 진동 없이 가장 빨리 경로에 붙는 선행점 p_d를 경로 위에서 고릅니다.
- **Dubins 경로란:** 최대 곡률(최소 반경 r_min) 원호와 직선을 조합한 최단 경로입니다. 시작 자세와 끝 자세(위치+방향)를 잇고, RSR·RSL·LSR·LSL·RLR·LRL 여섯 종류가 있습니다.
- **Dubins 경로의 역할:** 실제로 따라갈 경로가 아니라, **p_d를 고르는 잣대로만** 씁니다(논문에 따르면 p_d를 추종한 실제 궤적이 Dubins 경로와 비슷해짐).
- **r_min (식 4):** r_min(v_cmd) = v_cmd² / (9.79·(e_max + f_max))
  - 논문 값: e_max = 0(경사 없음), f_max = 0.05
  - 범위: [차량 최소회전반경, 12 m]로 자릅니다.
  - 효과: 빠를수록 반경이 커지고, 선행점도 멀어집니다.
- **순서:**
  1. 가장 가까운 경로점 p_w(인덱스 i_w)를 찾습니다.
  2. i_w 앞쪽 경로점 중 r_min ≤ ‖p_w − p_ref(i)‖ ≤ 탐색한계(논문 12 m)인 점들을 후보로 둡니다.
  3. 각 후보 i에 대해 Dubins 길이를 계산합니다.
     - 시작 자세: (x_v, y_v, **θcar + δ**) — 현재 조향각까지 반영
     - 끝 자세: (x_i, y_i, ψ_i) — ψ_i는 그 점의 경로 접선 방향
  4. **Dubins 길이가 가장 짧은 후보를 p_d**로 합니다.
- **직관:** 경로 위에서 방향까지 맞게 달리면 Dubins 길이는 그냥 직선 거리이므로 p_d ≈ r_min만큼 앞(속도에 따른 L_f)이 됩니다. 경로에서 떨어져 있거나 방향이 틀어져 있으면 Dubins 길이가 거리·방향 관계를 함께 반영해서 p_d의 위치를 바꿉니다.

### 2.4 제안 방법 Step 2 — p_d를 경로 밖 p_l로 옮기기 (논문 3.2절, 식 5–10)
- **목적:** 코너 진입 시 코너 컷팅을 줄입니다.
- **문제:** p_d를 그대로 따라가면 앞바퀴가 p_w→p_d 방향(p_wd)을 향합니다. 그러면 p_w에서의 접선 방향(p_wl)에서 벗어나 코너 안쪽으로 들어갑니다.
- **해결:** p_l을 **p_w의 접선 위로**(코너 바깥쪽으로) 옮깁니다.
  - φ = ψ(p_w) − ∠p_wd  (식 7의 θ. 접선과 p_wd 사이 각)
  - |p_dl| = |p_wd|·tan|φ|  (식 6) — p_d에서 p_wd에 수직으로 이만큼 가면 정확히 p_w의 접선 위에 닿습니다.
  - p_l = p_d + **τ**·|p_dl|·(cos θ_pdl, sin θ_pdl)  (식 5)
- **얼마나 옮길지(τ, 식 8–10):** **τ = (1 − α)·β**
  - α = min(‖p_v − p_w‖ / α_max, 1) — 차가 경로에 가까울수록 0에 가까워집니다(식 9).
  - β = 0 (κ_w ≥ κ_d일 때), 아니면 min((κ_d − κ_w) / β_max, 1) — 앞쪽 곡률이 더 클 때(코너 진입)만 커집니다(식 10).
  - 결과: 직선 주행이나 코너 탈출에서는 τ ≈ 0(p_l = p_d)이 되고, 경로에 붙은 채 코너에 진입할 때만 τ → 1이 됩니다.
- **논문 최적 파라미터:** α_max = 5, β_max = 0.2 (Table 1, 평균 횡오차 0.109 m). 곡률이 더 큰 경로면 α_max는 크게, β_max는 작게 잡으라고 권합니다.
- **최종 조향:** p_l로 2.1의 원과 식(3)을 그대로 적용합니다. 이때 η, L_f는 p_v와 p_l로 다시 계산합니다.

### 2.5 매 스텝 알고리즘 (구현 시 순서)
```
입력: 상태 (x, y, θcar, v, δ), 경로 ref(x, y, s, ψ, κ), 파라미터
1. p_w  ← 이전 인덱스 주변 창에서 최근접 경로점 (폐루프: 인덱스 mod N, 다른 구간으로 튀지 않게)
2. v_cmd ← 논문 4.1절 속도 규칙 (pp.v_mode = "curve", 모든 모드 공통)
           κ* = max(|κ(p_w)|, |κ(p_w에서 경로를 따라 r_min(v_tar) 앞)|)   ← 차 또는 선행점이 곡선 위
           v_cmd = min(v_tar, √(9.79·(e_max + f_max) / κ*))             ← 식 4를 v에 대해 풂
           (v_mode = "const"면 항상 v_tar)
3. r_min ← clip(v_cmd² / (9.79·f_max), R_veh, r_up)
4. Step 1: 후보 i (r_min ≤ ‖p_w − p_i‖ ≤ d_search) 에 대해 Dubins 길이 → 최소인 p_d
5. Step 2: φ, |p_dl|, θ_pdl, α, β, τ → p_l
6. 원/조향: η = wrap(∠(p_l − p_v) − θcar), L_f = ‖p_l − p_v‖, κ = 2 sin η / L_f,
           R = 1/κ, 원 중심 o, δ_cmd = clip(atan(κL), ±δmax)
7. 출력 u = (δ_cmd, v_cmd), dbg = {p_w, p_d, p_l, L_f, η, κ, R, o, r_min, α, β, τ, φ, Dubins 길이}
```

### 2.6 우리 차·맵에 맞춘 시작 파라미터 (검토·튜닝 대상)
논문 차량(Hyundai HG240, 축간거리 약 2.85 m — 차량 제원이며 논문에는 없음)과 우리 차(L = 0.59 m)의 비율은 약 **0.21**입니다. 길이 파라미터는 이 비율만큼 줄이고, 곡률 파라미터는 반대로 키웠습니다.

| 파라미터 | 논문 | 시작값 | 메모 |
|---|---|---|---|
| e_max, f_max | 0, 0.05 | 0, 0.05 | 식(4) 그대로 |
| r_min 범위 | [최소회전반경, 12 m] | **[1.02 m, 2.5 m]** | v=1.0 → 2.04 m, v≤0.7 → 1.02 m |
| 후보 탐색 한계 | 12 m | **2.5 m** | |
| α_max | 5 m | **1.0 m** | ×0.21 |
| β_max | 0.2 1/m | **0.95 1/m** | ÷0.21 (곡률은 길이의 역수) |
| 목표속도 v_tar | 1.33–5.55 m/s | **0.5–1.0 m/s** | vMax 1.5. 곡선 감속(2.5의 2번)은 f_max 0.05, 최대 곡률 0.561에서 v_tar > 0.93일 때만 걸림 |
| 경로점 간격 | 0.01 m | 0.01 m | 논문: Catmull-Rom 0.01 m |
| 맵 곡률(예상) | 0.04–0.2 1/m | 약 0.25–0.5 1/m (반경 2–4 m) | 경로 추출 후 확인. 차 최대곡률 0.98보다 작아서 주행 가능 |

### 2.7 구현할 때 주의할 점
- **θ가 두 가지 뜻으로 쓰임:** 논문에서 θ는 식(2)–(3)에서는 선행점 방향각, 식(6)–(7)에서는 접선과 p_wd 사이 각입니다. 코드에서는 η와 φ로 나눠 부릅니다.
- **식(6)의 부호:** 식(7)의 정의(θ = θ_pwl − θ_pwd)를 그대로 넣으면 그림 4와 반대쪽으로 옮겨집니다. 기하적으로 맞는 식은 **θ_pdl = ∠p_wd + sign(φ)·π/2**(p_l이 p_w 접선 위에 오는 쪽)입니다. 왼쪽 코너에 들어갈 때 p_l이 바깥(오른쪽)에 생기는지 테스트로 확인합니다.
- **β의 곡률:** 우리 트랙에는 좌·우 곡선(T4 근처의 S자)이 섞여 있으므로 곡률은 **크기 |κ|**로 비교합니다.
- **폐루프:** 인덱스는 순환(mod N)으로 다룹니다. 최근접점은 이전 인덱스 주변에서만 찾아서, 가까운 다른 구간으로 튀지 않게 합니다.
- **Dubins 계산량:** `dubinsConnection`은 후보 수만큼 계산합니다(예: 2.5 m / 0.01 m = 250개 × 50 Hz). 먼저 후보를 2–5 cm 간격으로 솎고, `comp_ms`를 기록해 보고 조정합니다. 느리면 길이만 구하는 해석식 함수를 직접 만듭니다.

### 2.8 선행점 위치를 파라미터로 조절하는 방식 — 조사와 의견
**의견: 찬성합니다.** 다만 "선행점 고르는 방식(모드)"과 "그 방식의 손잡이(파라미터)"를 나눠서 파라미터로 고르게 하는 구조를 권합니다. 이유는 세 가지입니다.

1. **표준 구현들이 이미 이렇게 합니다.**
   - MATLAB `controllerPurePursuit`: `LookaheadDistance` 하나가 주 튜닝 손잡이입니다. 문서에도 크면 코너를 자르고 작으면 진동한다고 나옵니다.
   - ROS2 Nav2 Regulated Pure Pursuit: 고정 거리(`lookahead_dist`)와 속도 비례(`lookahead_time`·v를 `min/max_lookahead_dist`로 자름)를 스위치(`use_velocity_scaled_lookahead_dist`)로 고릅니다.
2. **논문 자체가 비교 실험 구조입니다.**
   - 기준선 비교: Prop. to Speed / Offset / 제안 방법
   - 파라미터 비교: α_max × β_max 9조합 (Table 1)
   - 단계별 효과: Step 1, Step 2 각각 (4.4, 4.5절)
   → 모드와 파라미터만 바꿔 같은 경로·같은 조향식으로 돌려야 MSE 비교가 공정합니다.
3. **한 번 정한 값이 다른 상황에 잘 옮겨가지 않습니다.** 최근 연구들도 속도·곡률 스케줄을 손으로 정하면 트랙과 속도가 바뀔 때 잘 맞지 않는다고 지적합니다. 논문도 결론에서 α_max·β_max를 상황별로 정해야 한다고 했습니다. 그래서 값을 코드에 박지 않고 바꿔 가며 실험할 수 있어야 합니다.

**구조 — 선행점 선택만 갈아 끼우고, 원→조향은 공통:**
```
pp = pp_params();                     % 모드 + 파라미터를 한 곳에서 (run.mat에 함께 저장)
[p_l, dbg] = select_lookahead(st, ref, pp, mem)   % ← 모드별로 다른 부분은 여기뿐
[δ_cmd, dbg] = pursuit_steer(st, p_l, p)          % 원(κ = 2 sin η / L_f) → δ = atan(κL), 모든 모드 공통
```

| 모드 | 선행점 정하는 법 | 파라미터 (우리 차 시작값) | 용도 |
|---|---|---|---|
| `fixed` | 경로를 따라 L_f 앞 | L_f = 0.8 m (비교용 0.6 / 1.5 / 2.3 = 논문 3 / 7 / 11 m × 0.21) | 가장 기본 기준선 |
| `speed` | L_f = clip(t_la·v, L_min, L_max) | t_la = 1.2 s, L_min = 0.6 m, L_max = 2.5 m | 논문의 "Proportional to Speed" 기준선, Nav2 방식 |
| `paper` | Step 1 (Dubins) + Step 2 (τ) | f_max = 0.05, r_min 범위 [1.02, 2.5] m, 탐색 2.5 m, α_max = 1.0 m, β_max = 0.95 1/m, `step1_on`, `step2_on` | 제안 방법. 스위치로 Step 1만 / Step 1+2 비교 |
| (선택) `offset` | 논문 2.3.2 Andersen 방식 | 오프셋 D | 두 번째 기준선이 필요하면 추가 |

**`paper` 모드에서 주의할 점:** L_f를 직접 정하는 파라미터는 없습니다. 경로 위에서는 선행점 거리 ≈ r_min(v) = v²/(9.79·f_max)가 되므로, **f_max가 사실상 "얼마나 멀리"를 정하는 손잡이**입니다(작을수록 멀어짐). α_max·β_max는 "언제·얼마나 바깥으로 옮길지"를 정합니다. 모드가 달라도 실제로 쓰인 L_f는 매 스텝 기록되므로 같은 축에서 비교할 수 있습니다.

**값을 바꾸는 방법:**
- **기본:** `pp_params.m`의 기본값 + 실행 시 이름-값 덮어쓰기
  - 예: `pure_pursuit_control('mode','speed','t_la',1.0)`
  - 실행 폴더 이름에 모드가 들어가고, 모든 파라미터가 `run.mat`에 저장됩니다.
- **일괄 비교:** Unity 없이 빠른 오프라인 모드로 값 목록을 자동으로 돌립니다(논문 Table 1처럼). 결과 폴더별 MSE를 나중에 표로 모읍니다.
- **실시간 조절(탐색용):** MATLAB 그림에 슬라이더를 두어 주행 중에 바꾸면, 원과 선행점이 어떻게 변하는지 눈으로 볼 수 있습니다.
  - 단, **분석에 쓸 데이터는 한 실행 동안 값을 고정**하길 권합니다. 중간에 바뀌면 MSE가 어느 값의 결과인지 섞이기 때문입니다.
  - 실시간으로 바꿨다면 그 값도 매 스텝 열로 기록하고 `summary.txt`에 "파라미터 변경됨"을 표시합니다.

**참고:**

- Nav2 Regulated Pure Pursuit 설정 (https://docs.nav2.org/configuration/packages/configuring-regulated-pp.html)
- Elgouhary & El-Wakeel, PPO로 lookahead 학습 (https://arxiv.org/abs/2602.18386)

## 3. 레퍼런스 경로 — "현재 위치에서 차선 따라 주행"
**대상:** 차가 지금 서 있는 **바깥 차선의 중심선**. Start 선에서 출발해 반시계 방향으로 한 바퀴 돕니다(우측통행). 이미지에서 이 차선은 바깥 흰 실선과 가운데 점선 사이입니다(폭 약 0.8–0.94 m, 차폭 0.56 m).

### 권장: 맵 텍스처에서 자동 추출 (MATLAB 기본 기능만 사용, 재현 가능)
1. `imread(Assets/image.png)` → 색으로 아스팔트(진회색) / 흰 페인트 / 주차장(밝은 회색) / 잔디를 나눕니다.
2. 도로 마스크 = 아스팔트 + 도로 위 흰 페인트. 점선 틈·횡단보도·Start/T 표시선은 `conv2` 기반 팽창·침식으로 메웁니다(Image Processing Toolbox가 없어서 직접).
3. `contourc`로 도로 마스크의 경계선 두 개(바깥 가장자리, 안쪽 가장자리)를 얻습니다.
4. 픽셀 → 월드 변환: **x = 8.5 − 17·(px+0.5)/1949, y = −5.5 + 11·(py+0.5)/1462**. 가로·세로 축척이 달라서(0.0087 / 0.0075 m/px) 반드시 월드 좌표에서 계산합니다.
5. 두 경계를 호길이로 다시 샘플링한 뒤 차선 중심 = 바깥 + 0.25·(안쪽 − 바깥)으로 잡습니다(두 차선 폭이 같음: 이미지에서 110 px / 105 px). 가운데 점선과 비교해 검증합니다.
6. 주기형(폐루프) 스무딩을 하고 0.01 m 간격으로 재샘플링한 뒤 s, ψ, κ를 계산합니다. κ도 약하게 스무딩합니다. κ가 β 계산에 들어가서 노이즈에 민감하기 때문입니다.
7. 시작점은 차 위치 (7.20, −0.89)에 가장 가까운 점, 방향은 차 방향(+Z, 반시계)과 같게 정렬합니다.
8. `reference_path_outer_lane.csv/.mat`로 저장한 뒤 **두 곳에서 눈으로 검증**합니다.
   - MATLAB: 이미지를 월드 좌표로 깔고 그 위에 경로를 그립니다.
   - Unity: Top 뷰에 LineRenderer로 경로를 그립니다.
