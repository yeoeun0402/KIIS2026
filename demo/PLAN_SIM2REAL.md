# 실차 Plant 구축 계획: Unity 인계 직전까지 (v0.1)

작성 2026-11-21 · 짝 문서 `INTERFACE.md` (u·y 규약) · 기준 그림 `system_block.png`

## 0. 목표와 범위

**최종 목표(전체):** 실차가 2차선을 한 바퀴 도는 동안 Unity의 controller K와 observer가 루프를 닫고, 그 결과를 Unity에서 시뮬레이션과 같은 조건으로 비교해 봅니다.

**이 계획의 범위:** 그림의 plant(파란 점선)와 측정 C까지입니다. Unity 개발자가 자기 프로젝트에 붙이기만 하면 되는 상태로 넘깁니다.

인계물 (= 완료 조건):
1. `INTERFACE.md` 확정판과 그것을 구현한 ROS 노드 (`/plant/u` → 실차 실행, 실차 → `/plant/y`, `/plant/y_aux`)
2. 정확도를 검증한 y: 지도, 장착값, 측정 잡음 R, 지연 T_y
3. 정의대로 실행되는 u: 조향 위치 루프, 속도 루프
4. `plant_params.yaml`: L, δmax, τ_v, τ_δ, δ̇max, 데드밴드, T_u, T_y. 그리고 식별 데이터셋과 재현 스크립트
5. 시험용 대역 제어기로 돈 2차선 한 바퀴 기록 (bag + `INTERFACE.md` §4 CSV)

**원칙**
- **측정 KF와 observer를 섞지 않습니다** (`INTERFACE.md` §0.1). plant 쪽 필터는 u도 운동 모델도 쓰지 않습니다.
- 수동 주행은 **측정·식별용**으로만 씁니다. 완료 판정은 u를 받아 돈 주행으로 합니다.
- 원본(`~/car_drive_exp`, `~/aruco-slam`)은 손대지 않습니다. 펌웨어도 `car_drive_exp_copy` 복사본만 고칩니다.
- 단계마다 숫자로 된 통과 기준이 있습니다. 통과하지 못하면 다음 단계로 넘어가지 않습니다.

### P1. 측정 y 파이프라인 🖥 (기존 세션 영상으로 개발·시험)
그림의 C 블록을 규약대로 만드는 단계입니다. **state 품질의 출발점이라 가장 먼저 합니다.**

**P1-1 고정 지도 로컬라이제이션 모드**

- 측정 KF는 zero-motion으로 유지합니다(u 없음, 운동 모델 없음). 차 자세는 바닥 위 SE(2)로 구속하고, 높이와 기울기는 장착값으로 고정합니다(build_map과 같은 가정).
- 지도에 없는 마커는 무시하고 `/aruco/unknown`으로 알립니다.

**P1-2 y 공분산과 품질 정보**
- 매 프레임 (X, Y, θ) 3×3 공분산을 냅니다. EKF 공분산을 base_link 2D로 변환하거나, 프레임 단위 PnP 잔차로 추정합니다. 둘 중 어느 쪽이 실측 잡음과 맞는지 P2에서 판정합니다.
- 추가로 n_markers, reproj_rms_px, latency를 냅니다.

**P1-3 `plant_io` 노드의 측정 쪽**
- `/plant/y`: 위 자세, 공분산, `valid`, 편의 채널 s·e_y·e_θ(`lane2_centerline.csv` 투영, 기하 변환만)
- `/plant/y_aux`: 엔코더 v(창 평균 차분, 운동 모델 없음), POT δ
- **엔코더·POT 시각 처리:** 보드 `millis`를 ROS 시각으로 맞춥니다. 수신 시각 − millis의 하한을 추적하는 방식입니다. 그러려면 `wasd_drive`/시리얼 링크가 보드 ms를 버리지 않게 고쳐야 합니다.

**P1-4 기록**
- `INTERFACE.md` §4 CSV를 내보내는 `plant_export`를 만듭니다(bag → CSV).

**P1-5 시험**
- 세션 20261121_051209와 11/20 필드 세션 영상을 `video_publisher`로 재생합니다.

**P2-2 현장 확인**
- 출발선이 도면의 'Finish 100' 선인지 확인

**P2-3 지도 주행**
- 2차선을 천천히 **한 바퀴 이상** 돌고, 출발 전 3초 정지합니다.
- `build_map.py --align auto`로 빌드합니다.
- 지도는 `track/maps/<날짜>/`로 버전을 붙여 고정합니다.

**P2-4 정확도 검증 (고정 지도 모드로)**
- **정지 잡음:** 검사점마다 차를 세우고 10초 → y 표준편차. 이 값이 R의 참고값입니다.
- **절대 정확도:** 검사점에 차를 놓았을 때 y와 줄자 좌표의 차이
- **출발 재현성:** 출발선에 차를 3번 다시 놓고 y의 퍼짐
- **주행 중 일관성:** 한 바퀴 동안 e_y 그래프(수동 주행이라 절대 정답은 아님)와 끊김 구간 길이
- P1-2 공분산과 실측 잡음을 비교해 공분산 방식을 확정합니다.

**통과 (잠정, 차선 폭 0.85 m 기준)**

- 정지 잡음 σ ≤ 1 cm, σ_θ ≤ 0.5°
- 한 바퀴 동안 `valid=false` 연속 구간 ≤ 0.3 s

### P3. 입력 u 실행 (구동 계층) 🖥 → 🚗 (바퀴 띄움 → 바닥)
`INTERFACE.md` §2.2의 u = [v_cmd, δ_cmd]를 차가 실제로 따르게 만드는 단계입니다. 이 내부 루프는 **plant의 일부**입니다. Unity의 K와 observer가 보는 것은 이 루프까지 포함한 동특성입니다.

**P3-1 펌웨어 (복사본) 🖥**
- 보율을 115200으로 올립니다(호스트 `serial_link`도 함께).
- `T<pot>\n`: 조향 목표 POT 명령. 아두이노 루프(≥ 200 Hz)에서 PD와 데드밴드로 조향 모터 PWM을 연속 제어하고, 한계 POT에서 차단합니다.
- `W<counts_per_s>\n`: 목표 바퀴 속도 명령. 엔코더 차분과 PI + 피드포워드(PWM 표)로 동작합니다.
  - 루프를 아두이노에 두는 이유: 엔코더가 거기 있고, 호스트 왕복 지연이 없습니다.
- 기존 `V`, `L/R/F`, `G/S`는 RAW·수동용으로 그대로 둡니다.
- 텔레메트리 `P`, `E`를 50 Hz로 올리고, 실제 적용값 `A <pwm> <pot_target>`을 추가합니다.
- 워치독을 유지합니다(명령 두절 시 정지).
- `fake_board.py`에 같은 프로토콜을 넣어 차 없이 시험합니다.

**P3-2 δ 보정 🚗**
- 저속 원호 주행으로 조향 단계별 반경 R을 재고, δ_eff = atan(L/R)로 POT↔δ 표를 만듭니다(`steer_calib`).
- 좌우 대칭과 히스테리시스를 측정합니다.
- 결과: δmax 좌/우, 역변환 δ_cmd → pot_target

**P3-3 거리 환산 🚗**
- 직선 5 m를 3번 굴려서 카운트/m를 구합니다(바퀴를 손으로 밀어서 한 번, 주행으로 한 번).
- 엔코더와 바퀴 사이의 기어비를 확인합니다.

**P3-4 `plant_io` 노드의 입력 쪽 🖥**
- `/plant/u` → 포화 → 단위 변환(δ → pot_target, v → counts/s) → 시리얼
- `/plant/u_applied` 발행
- 안전: u 워치독 0.3 s, y 끊김 0.5 s, e-stop, 트랙 범위 이탈 → 정지. `/plant/status` 발행

**P3-5 응답 시험 🚗 (바퀴 띄움 → 바닥 저속)**
- δ 계단(±5°, ±10°, 최대) / v 계단(0.3, 0.5, 0.8 m/s 등)

**통과**
- δ 정착 오차 ≤ 1°, 오버슈트 ≤ 20%, 진동 없음
- v 정상상태 오차 ≤ 5% 또는 0.03 m/s, 오버슈트 ≤ 20%
- u 워치독과 e-stop이 0.1 s 안에 정지 (바퀴 띄우고 확인)
- 30 Hz u를 넣었을 때 시리얼 유실 0, `u_applied` 지연 < 10 ms

### P4. 시스템 식별 🚗⛳
Unity의 A·B와 observer의 L(또는 Q·R)을 실차에 맞추기 위한 데이터와 숫자를 만드는 단계입니다.

**P4-1 실험** (모두 `/plant/u`로 입력을 넣어 기록. 수동 조작 아님)

| 실험 | 입력 | 얻는 것 |
|---|---|---|
| 조향 계단·스윕 (정지 + 저속) | δ_cmd 계단, 0.2~3 Hz 사인 | τ_δ, δ̇max, 데드밴드, 지연 |
| 속도 계단 | v_cmd 계단 (여러 크기, 가속·감속) | τ_v, 지연, 정지 마찰 구간 |
| 정상 원 선회 | δ 고정 여러 값 × 속도 2가지 | 유효 L 검증 (θ̇ = v tanδ / L), 미끄러짐 |
| 지연 측정 | u 계단 시각 → POT·엔코더 반응 → y 반응 | T_u (명령→구동), T_y (카메라→y) |
| 정지 잡음 | 정지 30 s × 검사점 | R (P2 값 보강) |

**P4-2 적합과 검증**
- `INTERFACE.md` §2.1 모델의 파라미터를 적합합니다.
- 기록된 u_applied를 모델에 넣어 예측한 궤적과 y를 비교합니다. 예측 구간은 0.5 s와 2 s입니다.
- 산출물: `plant_params.yaml`, `sysid/` 데이터셋, 적합·검증 스크립트, 그래프

**통과**
- 0.5 s 앞 예측 위치 오차 중앙값 ≤ 3 cm, θ ≤ 2°
- 원 선회에서 구한 L이 실측 0.56 m와 ±5% 이내 (벗어나면 δ 보정 재검토)

### P5. 루프 시험과 한 바퀴 🚗⛳
plant가 외부 제어기의 u를 받아 루프를 닫을 수 있는지 확인하는 단계입니다. **여기서 쓰는 제어기는 연결 시험용 대역입니다.** 최종 제어기는 Unity의 K와 observer입니다.

**P5-1 대역 제어기 `stub_controller` 🖥**
- 별도 노드로 둡니다. `/plant/y` → Pure Pursuit(조향) + 고정 v_ref → `/plant/u`
- Unity와 같은 토픽만 쓰므로 나중에 Unity로 바꾸기만 하면 됩니다.
- 시뮬 시험: `plant_params.yaml` 모델과 가상 측정 잡음으로 만든 가짜 plant(`sim_plant`)에 붙여 봅니다.

**P5-2 단계적 실차 🚗**
1. 바퀴 띄움: u 흐름, 부호, 정지 동작
2. 직선 한 구간 저속 (0.3 m/s)
3. 곡선 포함 반 바퀴
4. 한 바퀴 저속
5. 한 바퀴 목표 속도 (Unity 시뮬 조건과 같은 v_ref)

**P5-3 기록과 인계 패키지**
- 각 주행의 bag과 `plant/` CSV를 남깁니다.
- `handoff/` 폴더: `INTERFACE.md` v1.0, `plant_params.yaml`, 지도, mount, steer_calib, `sysid/`, 한 바퀴 기록, 실행 방법 `README`

## 3. 순서와 의존 관계

```
P0 규약 ──┬──▶ P1 측정 y (🖥) ───────────▶ P2 y 정확도 (🚗⛳) ──┐
          │                                                    ├──▶ P4 식별 (🚗⛳) ──▶ P5 루프·한 바퀴 (🚗⛳) ──▶ 인계
          └──▶ P3-1·P3-4 펌웨어·plant_io (🖥) ──▶ P3-2~5 (🚗) ──┘
```
- **차 없이 먼저 할 것:** P0, P1 전체, P3-1, P3-4, P5-1, P2-1
- **현장 1회차 (매트 + 차):** P2-2~4, P3-2·3·5 → 같은 날 가능하면 P4 일부
- **현장 2회차:** P4 나머지, P5-2

## 4. 첫 번째 할 일
**P1-1 고정 지도 로컬라이제이션 모드**부터 합니다.
- y가 그림의 출발점이고, 지금 구조(매번 새 SLAM + 사후 정합)로는 주행마다 좌표계가 달라집니다. 규약의 "track 좌표 y"가 성립하지 않습니다.
- 차 없이 기존 세션 영상으로 개발하고 시험할 수 있습니다.
- 동시에 P0(Unity 개발자 검토 요청)을 보내 두면 기다리는 시간이 겹칩니다.

## 5. 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 마커 끊김 구간 | y 공백 → observer 예측만으로 버텨야 함 | P2에서 보강, 보조 측정 v_enc·δ_pot 제공, 끊김 길이 통과 기준 |
| 매트 요철·비평면 | SE(2) 가정 오차 수 cm | 검사점으로 크기 확인, 공분산에 반영 |
| 9600 bps 한계 | 30 Hz 명령 불가 | P3-1에서 115200으로 |
| 조향 유격·히스테리시스 | δ 추종 오차, 중앙 부근 떨림 | 위치 루프 데드밴드, P3-2 히스테리시스 측정 |
| 바퀴 미끄러짐 | v_enc ≠ 실제 v, 유효 L 변화 | 저속 식별, 원 선회 두 속도 비교 |
| 출발 기준 불확실 (약 0.9 m 의심) | 지도 전체 이동·회전 | P2-2 현장 확인, `--align lane` 비교 |
| 카메라 재연결 시 초점·노출 초기화 | 검출률 저하 | `c920_camera` 5 s 점검 (이미 있음), 시작 체크리스트 |
| 디스크 부족 | 영상 잘림 (지난 지도 실패 원인) | 시작 전 여유 ≥ 30 GB 확인을 스크립트에 넣음 |
| Unity 좌표 원점 불일치 | 인계 후 전체 오프셋 | P0에서 확인 (`INTERFACE.md` §5) |
